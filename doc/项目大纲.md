## 0. 一句话定位

**LightORM = 表达式树 → SQL 的翻译器 + DbDataReader → 对象的反序列化器。**

它刻意不做变更追踪、不做一级缓存、不做复杂状态管理，只把两件事做到极致：

| 主线           | 输入                                     | 输出                                    |
| ------------ | -------------------------------------- | ------------------------------------- |
| **A. 表达式翻译** | `Expression<Func<T, bool>>` 等 LINQ 表达式 | SQL 字符串 + `DbParameter` 集合            |
| **B. 读取序列化** | `DbDataReader`                         | `Func<IDataReader, T>` 委托（动态编译 / 源生成） |

三条设计铁律贯穿全项目：

1. **零依赖** —— 核心库只用 `System.Linq.Expressions` + `System.Data.Common`
2. **三层职责分离** —— 解析器管"片段生成"、Builder 管"结构组装"、Adapter 管"方言翻译"
3. **源生成器替代反射** —— 用 Roslyn 生成器把实体元数据静态化，为 AOT 让路

## 3. 主线 A：表达式 → SQL

### 3.1 一条完整数据流

```
Expression<Func<T,bool>>
   │
   ▼ ExpressionResolver.Visit()          Utils/ExpressionResolver.cs
   │   switch 分派 11 种节点，边遍历边往 StringBuilder 追加片段
   ▼ ResolveContext                      Utils/ResolveContext.cs
   │   维护「参数表达式 → TableInfo(别名/索引)」映射，parent 链支持子查询回溯外层列
   ▼ ISqlMethodResolver                  Implements/BaseSqlMethodResolver.cs
   │   C# 方法调用 → SQL 函数 / 语法
   ▼ SelectBuilder.HandleResult()        Builder/SelectBuilder.cs
   │   按 SqlPartial 把片段分派到 Where/Join/Select/GroupBy/OrderBy/Having 容器
   ▼ SelectBuilder.Build()
   │   按固定顺序递归组装；子查询/CTE/Join子查询/Union 递归，level 控制缩进与别名层级
   ▼ IDatabaseAdapter
   │   标识符引用符、分页、布尔/日期字面量、JSON 函数
   ▼
SQL 字符串 + DbParameters
```

### 3.2 入口层：`IExpressionContext` 家族

```
IContext（Select/Insert/Update/Delete/QueryMultiple + Ado）
   └── IExpressionContext  ← 默认多库上下文，ExpressionCoreSql
          │  SwitchDatabase(key) → ITransientContext        (TransientContext)
          │  CreateScoped(key)   → ISingleScopedExpressionContext (SingleScopedExpressionCoreSql)
          └  CreateScoped()      → IScopedExpressionContext  (ScopedExpressionCoreSql，支持跨库事务)
```

切换的本质是更换底层 `SqlAdo` 绑定的 `DatabaseConnection`；三者共享同一套 `Select/Insert/Update/Delete` 入口（实现集中在 `ExpressionSql/ExpressionCoreSqlContextMethodImpl.cs`）。

### 3.3 流式接口体系

| 接口                                                                             | 文件                          | 承载                                                                              |
| ------------------------------------------------------------------------------ | --------------------------- | ------------------------------------------------------------------------------- |
| `ISql`                                                                         | `Interfaces/ExpSql/ISql.cs` | 标记接口，暴露 `DbContext/Executor/SqlBuilder/IsSubQuery`                              |
| `IExpSelect0<TSelect,T1>`                                                      | `IExpSelect0.cs`            | 与表数无关的能力：`Where/WhereIf/ToList/First/Count/Max/Min/Sum/Avg/Any/Distinct/AsTemp` |
| `IExpSelect<T1>`                                                               | `IExpSelect`1.cs\`          | 加 `Join*/OrderBy*/GroupBy/Include/Union/WithTempQuery`                          |
| `IExpSelect<T1,T2>`                                                            | `IExpSelect`2.cs\`          | 双表 Join/Where/OrderBy + `TypeSet<T1,T2>` 扁平投影                                   |
| `IExpSelect<T1..T16>`                                                          | **源生成器产出**                  | 每 Join/WithTemp 一张表升一阶泛型                                                        |
| `IExpSelectGroup<TGroup,TTables>`                                              | `IExpSelectGroup.cs`        | 分组后上下文，暴露 `IExpSelectGrouping` 聚合/窗口函数                                          |
| `IExpTemp<T>`                                                                  | `IExpTemp.cs`               | CTE 临时表                                                                         |
| `IExpInsert<T>` / `IExpUpdate<T>` / `IExpDelete<T>` / `IExpInclude<T,TMember>` | 同名文件                        | 写操作与导航加载                                                                        |

**为什么需要 16 个泛型版本？** LightORM 用泛型参数个数编码"当前已 Join/WithTemp 的表元组"，让 `Where/OrderBy/Select` 的 lambda 能对全部已参与表做强类型访问。`InnerJoin` 返回 `SelectProvider{n+1}`，每加一表升一阶，16 是工程上限。这些重载全部由 `LightOrmExtensionGenerator` 机械展开生成，避免手写数百个近乎相同的类。


### 3.4 Provider 门面层（`src/LightORM/Providers/`）

Provider 是**门面 + Builder 持有者**，把流式调用翻译成对 Builder 片段容器的写入；Builder 在 Join 后通过 `new SelectProviderN(同一 builder)` 在多个 Provider 间传递，实现链式状态共享。

| Provider                              | 文件                                         | 对应 Builder                         |
| ------------------------------------- | ------------------------------------------ | ---------------------------------- |
| `SelectProvider0/1/2`                 | `Providers/Select/*.cs`                    | `SelectBuilder`                    |
| `SelectProvider3..16`                 | 源生成器产出                                     | 同上                                 |
| `SelectInsertProvider`                | `Providers/Select/SelectInsertProvider.cs` | `InsertBuilder`（INSERT ... SELECT） |
| `GroupSelectProvider<TGroup,TTables>` | `Providers/GroupSelectProvider.cs`         | `SelectBuilder` + 聚合展平             |
| `IncludeProvider<T1,TMember>`         | `Providers/IncludeProvider.cs`             | `SelectBuilder.Includes`           |
| `TempProvider<T>`                     | `Providers/Select/TempProvider.cs`         | `SelectBuilder`（IsTemp）            |
| `InsertProvider<T>`                   | `Providers/InsertProvider.cs`              | `InsertBuilder<T>`                 |
| `UpdateProvider<T>`                   | `Providers/UpdateProvider.cs`              | `UpdateBuilder<T>`                 |
| `DeleteProvider<T>`                   | `Providers/DeleteProvider.cs`              | `DeleteBuilder<T>`                 |

典型落点：`Where(exp)` → `SelectHandleExtensions.WhereHandle` → `SqlBuilder.Expressions.Add(new ExpressionInfo(SqlResolveOptions.Where, exp))`。


### 3.5 Builder 组装层（`src/LightORM/Builder/`）

`SqlBuilder`（抽象基类）持有 `Expressions`、`ResolveCtx`、`DbParameters` 与 `ResolveExpressions()`；`SelectBuilder` 继承它并维护片段容器：

| 容器                                               | 内容                             |
| ------------------------------------------------ | ------------------------------ |
| `SelectValue`                                    | SELECT 投影（默认 `*`）              |
| `Where: List<string>`                            | 最终用 `AND` 连接                   |
| `joins: List<JoinInfo>`                          | 每个 JoinInfo 自带 `Where`         |
| `GroupBy` / `GroupingSets`                       | 分组 + ROLLUP/CUBE/GROUPING SETS |
| `OrderBy: List<string>` / `Having: List<string>` | 排序与分组过滤                        |
| `IsDistinct` / `Skip` / `Take`                   | 去重与分页                          |
| `Unions: List<UnionItem>`                        | UNION / UNION ALL              |
| `TempViews: List<SelectBuilder>`                 | CTE                            |
| `SubQuery` / `IsTemp` / `TempName`               | 子查询与临时表                        |
| `Includes: SortedSet<IncludeInfo>`               | 导航属性加载                         |

**四个关键方法**

- `ResolveExpressions(database)` —— 遍历 `Expressions`，每条调 `exp.Expression.Resolve(options, ctx)`，结果交给 `HandleResult` 按 `SqlPartial` 路由；完成后置 `IsCompleted` 防重复解析
- `HandleResult` —— `switch(SqlPartial)` 分发；遇导航属性触发 `ScanNavigate`
- `Build(StringBuilder, database, level)` —— 按 `WITH → SELECT [DISTINCT] → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → Paging → UNION` 顺序递归拼装
- `EstimateSqlLength()` —— 先预估容量再向 `StringBuilderPool` 租预分配的 StringBuilder，避免扩容拷贝

`SqlPartial` 枚举值：`None, Select, SelectFunc, Insert, Update, UpdateVersionColumn, Delete, UpdatePartial, Ignore, Join, Where, GroupBy, OrderBy, Having`。

**`ScanNavigate`（导航属性自动 JOIN）**：检测到 `UseNavigate` 后递归展开——一对多经中间表需 **2 次 JOIN**，一对一 **1 次**，嵌套导航递归下降（`NavigateDeep` 递减）。


### 3.6 表达式翻译层（核心引擎）

#### `ExpressionResolver`（`Utils/ExpressionResolver.cs`，674 行）

`Visit` 用 switch 模式匹配分派 11 种节点：

| 节点                      | 翻译                                                                  |
| ----------------------- | ------------------------------------------------------------------- |
| `LambdaExpression`      | 登记参数 → `Context.HandleParameterExpression`                          |
| `BinaryExpression`      | 左右递归 + `OperatorParser` 运算符；Where/Join/Select 语境自动加括号               |
| `ConditionalExpression` | `CASE WHEN ... THEN ... ELSE ... END`                               |
| `MethodCallExpression`  | 委托 `ISqlMethodResolver`；`get_Item` 走索引器语义                           |
| `NewArrayExpression`    | `IN (...)` 列表                                                       |
| `NewExpression`         | SELECT 投影 + `AS` 别名                                                 |
| `UnaryExpression`       | `Not` → 置 `IsNot` 标志位；`Convert` → 置 `IsVisitConvert`                |
| `ParameterExpression`   | 表别名；Select 语境展开为 `alias.*`；Insert 语境展开全部列                           |
| `MemberInitExpression`  | 投影绑定 + 别名                                                           |
| `MemberExpression`      | **列名**（`Expression` 是 Parameter）vs **值**（`Expression` 是闭包 Constant） |
| `ConstantExpression`    | 字面量 / 参数占位符                                                         |

**精妙细节**

- **索引器双重语义**：`int` 索引 → JSON 数组 `[3]`；`string` 索引 → JSON 对象 `["prop"]`
- **`IsNot` 标志位**：`Not` 节点置位，后续 `Contains`/`In` 消费它生成 `NOT LIKE` / `NOT IN`
- **列名 vs 值判定**：`MemberExpression.Expression` 是 `ParameterExpression` → 列；是 `ConstantExpression` → 闭包变量值
- **null 处理**：`Equal` + null → `IS NULL`；值侧生成 8 位随机占位名，延后到 `ReplaceConstantValue` 统一替换

#### `ResolveContext`（`Utils/ResolveContext.cs`）

解析期上下文枢纽：

- `parent` 链 + `Depth = parent.Depth + 1` —— 子查询引用外层列时 `GetTable` 沿链向上回溯
- `lambdaParameterInfos: Dictionary<ParameterKey(Type,Name?), TableInfo>` —— 参数 → 表/别名/索引
- `ParameterPrefix` —— 逐层加 `_` 后缀，隔离同名参数
- `HandleParameterExpression` / `GetTable` / `SetParamPrefix`

#### `ISqlMethodResolver`（`Implements/BaseSqlMethodResolver.cs`，719 行）

用 `Dictionary<string, Action>` 注册方法名 → 翻译动作。

**基类直接实现**：`Format / Result / Exits / In / Count / CountDistinct / Sum / Average / Max / Min / Abs / Round / Nvl / IsNull / Coalesce / Grouping / Trim* / Join / Distinct / Separator / Where / WhereIf / Any / RowNumber / Lag / Rank / PartitionBy / OrderBy* / Value / Case / When / Then / Else / End`

**强制 Provider 重写**（基类 `throw NotSupportedException`）：`ToString`、`StartsWith`、`Contains`、`EndsWith`、`Substring`、`NullThen`、`JsonQuery`、`JsonSet` —— 字符串拼接、类型转换、空值处理、JSON 函数恰是各库差异最大处。

**子查询的优雅处理** —— 方法返回 `IExpSelect` 时识别为子查询，**递归复用整个 SelectBuilder 管线**而非表达式编译：

```csharp
public virtual void Exits(IExpressionResolver resolver, MethodCallExpression methodCall)
{
    var builder = methodCall.CreateSelectBuilder();
    builder.SetResolveParentContext(resolver.Context);   // 支持引用外层列
    builder.IsSubQuery = true;
    resolver.Sql.AppendLine(resolver.IsNot ? "NOT EXISTS (" : "EXISTS (");
    builder.Build(resolver.Sql, resolver.Context.Database, resolver.Level + 1);
    resolver.Sql.Append(')');
}
```

这也是 AOT 改造的关键——子查询不用表达式编译。

#### `IDatabaseAdapter`（`Interfaces/IDatabaseAdapter.cs`）

方言最高层抽象，成员包括：`Prefix` / `Emphasis`（参数前缀与标识符引用符）、`MethodResolver`、`UseIdentifierQuote` / `QuoteIdentifiers`、`DbCommandInit`、`Paging`、`ReturnIdentitySql`、`FormatBooleanValue` / `FormatDateTimeValue` / `HandleDateValue` / `HandleBooleanValue`、`IsKeyWord` / `AddKeyWord`、`HandleMultipleQuerySql` / `RewriteParameterReferences`、`HandleJsonColumn` / `HandleJsonParameter`、`HandleInsertOrUpdate` / `HandleBatchInsert` / `HandleBatchUpdate` / `HandleBatchDelete`。

`CustomDatabaseAdapter`（`Implements/CustomDatabaseAdapter.cs`，380 行）提供约 60 个保留字集合与批量操作通用 SQL 模板，分页/日期/JSON 默认 `throw NotSupportedException`。

### 3.7 缓存层：FNV-1a 哈希 + 结构/值分离

```csharp
private readonly record struct CacheKey(SqlAction SqlAction, ulong Hash);
private static readonly ConcurrentDictionary<CacheKey, ExpressionResolvedResult> cache = new();
```

**关键设计**

| 机制                    | 说明                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| FNV-1a 64 位           | `offset=0xCBF29CE484222325`，`prime=0x100000001B3`；喂入 NodeType、Type/Member/Method 的 MetadataToken |
| 参数名不参与哈希              | 默认 `includeParameterNames=false`，`VisitParameter` 只写类型不写名 → 结构相同的 lambda 共享缓存                    |
| 常量值不参与哈希              | `x.Age > 10` 与 `x.Age > 20` 命中同一项                                                                |
| `NeedToExtractValues` | 命中后单独调 `ExpressionValueExtract.Extract()` 重新抽取本次参数值                                              |
| `ContainVariable`     | 标记表达式是否含闭包变量，决定是否走值提取                                                                            |

即：**结构解析只做一次，变量值提取每次都做，两者分离**。这是 CTE 查询 135.6μs → 89.5μs 的原理。

`ExpressionValueExtract`（`Utils/ExpressionValueExtract.cs`，655 行）作为 `ExpressionVisitor` 从闭包常量中抽取运行时值；闭包 getter 编译成委托并按 `类型FullName_成员链名` 缓存，避免反射。

## 4. 主线 B：DbDataReader → 对象（反序列化委托）

> 严格说是**反序列化**（reader → 对象）。项目提供两条并行的委托生成路径。

### 4.1 两条路径对比

|        | 运行时动态编译路径                          | AOT 静态生成路径                                   |
| ------ | ---------------------------------- | -------------------------------------------- |
| 实现     | `SqlExecutor/ExpressionBuilder.cs` | `LightOrmTableContextGenerator` 源生成器         |
| 机制     | `Expression.Lambda(...).Compile()` | 编译期生成 C# 静态方法                                |
| 适用     | 任意类型（实体/匿名/元组/基础类型）                | 仅标注 `[LightTable]` 的具名实体                     |
| 产物     | `Func<IDataReader, T>` 委托，进程内缓存    | `ITableEntityInfo<T>.DataReaderDeserializer` |
| AOT 安全 | ❌ 依赖动态代码                           | ✅                                            |


### 4.2 运行时路径：`ExpressionBuilder` 全流程

入口 `BuildDeserializer<T>(DbDataReader reader)`：

```
GenerateCacheKey(type, reader)              ← 类型 FullName + 每列「列名:DataType:AllowDBNull」
   │  命中 dynamicDelegates 缓存？直接返回
   ▼
BuildFunc<Target>(reader, CultureInfo)
   │
   ├─ ParameterExpression recordInstanceExp = Parameter(typeof(IDataReader), "reader")
   ├─ DataTable schemaTable = reader.GetSchemaTable()     ← 取列可空性
   │
   ├─ 按目标类型四路分派 ──────────────────────────────┐
   │                                                    │
   ▼ Expression.Lambda<Func<IDataReader,Target>>(body).Compile()
```

#### 类型分派

| 目标类型                                                                 | 生成形态                                                    |
| -------------------------------------------------------------------- | ------------------------------------------------------- |
| `System.Tuple<...>`                                                  | `Expression.New(ctor, args)` —— 按构造参数位置取列，最多 7 元        |
| 基础类型（`int`/`string`/`Guid`/`DateTime`… 及可空版，见 `Ex.IsElementaryType`） | 只取第 0 列                                                 |
| 匿名类型                                                                 | `Expression.New(ctor, args)` —— 按**属性声明顺序**匹配 ctor 参数   |
| 具名实体                                                                 | `Expression.MemberInit(Expression.New(type), bindings)` |

具名实体还额外处理三类特殊列：

- **普通列** —— 跳过 `IsNotMapped / IsNavigate / IsAggregated / IsAggregatedProperty / IsJsonColumn`
- **JSON 列** —— 走 `GetTargetJsonExpression`
- **聚合列（Flat）** —— 按 `AggregateType` 分组，生成一个嵌套 `MemberInit`
- 列匹配规则 `MemberMatchesName`：`PropertyName` 或 `ColumnName` 与 `reader.GetName(i)` **忽略大小写**相等

#### 每个成员的表达式由三段拼成

```csharp
// ① 取值：reader.GetXxx(i)
Expression RecordFieldExpression = GetRecordFieldExpression(...);
// ② 转换：类型对齐 / Parse / Convert
Expression Converted = GetConversionExpression(RecordFieldType, RecordFieldExpression, TargetType, Culture);
// ③ 空值：AllowDBNull 则包一层三元
Expression final = AllowDBNull
    ? Expression.Condition(
        Expression.Call(reader, IsDBNull, Constant(i)),   // reader.IsDBNull(i)
        Expression.Default(TargetMemberType),
        Converted,
        TargetMemberType)
    : Converted;
```

生成的目标形态（源码注释原文）：

```csharp
reader => new T {
    Member0 = (T0)reader.GetInt32(0),
    Member1 = (T1)reader.GetString(1),
    Member4 = reader.IsDBNull(4) ? default(T4) : (T4)reader.GetDecimal(4),
}
```

#### 取值方法映射（`ExpressionBuilder.ReflectMethod.cs`）

`typeMapMethod: Dictionary<Type, MethodInfo>` 覆盖 `byte/sbyte/short/ushort/int/uint/long/ulong/float/double/decimal/bool/string/char/Guid/DateTime/byte[]`；未命中回退 `IDataRecord.GetValue`。

三个特殊类型用自定义静态辅助方法兜底（`ExpressionBuilder.ExternalHelper.cs`）：

| 方法                          | 用途                                               |
| --------------------------- | ------------------------------------------------ |
| `RecordFieldToUInt16/32/64` | 无符号类型：先 GetIntXx 再判负抛 `OverflowException`        |
| `RecordFieldToBytes`        | 先 `GetBytes(col,0,null,0,0)` 取长度再分配缓冲，空数据返回 `[]` |
| `CustomStringToBoolean`     | 宽松解析 `",是,1,Y,YES,TRUE,"`                        |
| `GetSafeIntermediateType`   | decimal 与浮点/整数互转的中间类型选择，防溢出与精度损失                 |

#### 类型转换矩阵（`GetConversionExpression`）

| 源 → 目标             | 策略                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 同类型 / 底层类型相同       | 原样                                                                                                                                                            |
| `string` → T       | `GetParseExpression`：`T.Parse(string, NumberFormatInfo)`；枚举走 `Enum.Parse(type, s, true)`；DateTime 带 `DateTimeFormatInfo`；bool 走宽松解析；不支持则抛 `LightOrmException` |
| T → `string`       | `Convert.ToString(src)`                                                                                                                                       |
| → `bool` / `bool?` | `Convert.ToBoolean(src)`                                                                                                                                      |
| `byte[]` → T       | `byte[]` 原样；`MemoryStream` → `new MemoryStream(bytes)`；其余抛异常                                                                                                  |
| 其余                 | `Expression.Convert`                                                                                                                                          |
| 目标为可空且未转换过         | 再包一层 `Convert` 到 `Nullable<T>`                                                                                                                                |

#### JSON 列

`GetTargetJsonExpression` 把取值结果交给 `StringDeserializer` / `BytesDeserializer`，即 `ExpressionBuilder.RecordFieldStringDeserializer(value, targetType)` → `ILightJsonHelper.Deserialize(value, targetType)`。目标类型通过 `Expression.Constant(TargetType)` 内联进表达式；JSON 类型集合由 `ExpressionBuilder.AddJsonTypeMap(type)` 注册。

#### 缓存键

```csharp
$"{type.FullName}|{列名}:{DataType}:{AllowDBNull}|{列名}:...|"
```

即"**类型 + 结果集 schema**"共同决定一份委托——同名类型在不同查询列结构下各自缓存一份。

### 4.3 AOT 路径：源生成器

`[LightORMTableContext]` 标注在 `partial class` 上 → 生成器扫描编译期所有 `[LightTable]` 实体 → 为每个实体生成 `LightORM.GeneratedTableContext.{Type}TableInfo.g.cs`，产出：

| 生成成员                                                                    | 说明                                                          |
| ----------------------------------------------------------------------- | ----------------------------------------------------------- |
| `private static Lazy<ITableColumnInfo[]> columns`                       | 延迟构建，`Columns => columns.Value`                             |
| `CollectColumnInfo()`                                                   | 纯 `new ColumnInfo(...)` 字面量，**零反射**                         |
| `Type / TableName / Schema / CustomName / TargetDatabase / Description` | 元数据                                                         |
| `static GetValue(col, target)`                                          | `switch(PropertyName)` 直读                                   |
| `static SetValue(col, target, value)`                                   | `switch(PropertyName)` 直写，Flat 属性自动 new 子对象                 |
| `HandleInclude / HandleIncludeAsync`                                    | AOT 安全的导航属性加载（替代反射版 `BindIncludeDatas`）                     |
| `DataReaderDeserializer`                                                | `Func<IDataReader, T>?`，指向 `Deserialize{T}FromDbDataReader` |
| `Deserialize{T}FromDbDataReader(reader)`                                | **静态反序列化方法**                                                |

同时生成一个聚合 partial 类，维护 `tableInfos/table_sets/table_gets` 三个字典并暴露 `GetTableInfo/GetSetMethod/GetGetMethod`（用 `IsAssignableFrom` 回退到基类/接口）。

### 4.4 AOT 判定与降级

```csharp
// AssemblyInfo.cs
public static bool AOTSupported = false;                       // 由 ExpressionSqlBuilder 置 true
public static bool IsAOTRuntime => !RuntimeFeature.IsDynamicCodeSupported && AOTSupported;
```

即：**只有同时满足「运行时不支持动态代码」且「用户配置了生成器上下文」两个条件，才算 AOT 运行时**。`EnsureReflectionAccess(type)` 在"不支持动态代码 + 非匿名类型 + 未启用 AOTSupported"时抛出带解决方案说明的 `NotSupportedException`。

AOT 下的行为差异：

| 位置                                                  | 行为                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------- |
| `IncludeContextExtensions.BindIncludeDatas`         | 抛 `LightOrmException`（反射 Include 不可用）→ 改用生成器产出的 `HandleInclude`        |
| `SqlExecutorExtensions.Query<T>(sql, object param)` | 抛 `NotSupportedException`，提示改调 `Execute<TParameter>`                   |
| `ExpressionBuilder` 匿名类型嵌套                          | `IsAOTRuntime` 时抛 `LightOrmException("嵌套的匿名类型会被裁剪")`                   |
| `LightOrmAotAnalyzer`                               | 编译期诊断 **TCGA00001**：程序集声明 `IsAotCompatible` 时对非 `Execute<T>` 的扩展方法调用告警 |
| 生成器诊断                                               | `TCG00001`（需实现 ITableContext）、`TCG00002`（生成异常）                         |

### 6.2 SqlServer vs Sqlite 差异一览

| 维度            | SqlServer                                                                                             | Sqlite                                              |   |    |   |       |
| ------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------- | - | -- | - | ----- |
| 分页            | `OFFSET n ROWS FETCH NEXT m ROWS ONLY`                                                                | `LIMIT skip, take`                                  |   |    |   |       |
| 引用符           | `[col]`                                                                                               | `` `col` ``                                         |   |    |   |       |
| 自增回写          | `SELECT SCOPE_IDENTITY()`                                                                             | `SELECT LAST_INSERT_ROWID()`                        |   |    |   |       |
| 日期字面量         | `CONVERT(DATETIME,'...',120)`                                                                         | 直接 `'yyyy-MM-dd HH:mm:ss'`                          |   |    |   |       |
| LIKE 拼接       | `'%'+@p+'%'`                                                                                          | \`'%'                                               |   | @p |   | '%'\` |
| 空值函数          | `ISNULL`                                                                                              | `IFNULL`                                            |   |    |   |       |
| `ToString` 日期 | `CONVERT(VARCHAR(MAX),col,style)` —— **把 .NET 格式串映射成 style code**（`"yyyy-MM-dd"`→23，`"yyyyMMdd"`→112） | `STRFTIME('%Y-%m-%d %H:%M:%S',col)`                 |   |    |   |       |
| JSON          | `JSON_VALUE` / `JSON_MODIFY`                                                                          | `JSON_EXTRACT` / `JSON_SET`（Binary 用 JSONB\_*）      |   |    |   |       |
| Upsert        | `MERGE INTO ... WHEN MATCHED`                                                                         | `INSERT ... ON CONFLICT(pk) DO UPDATE SET EXCLUDED` |   |    |   |       |
| 分组聚合          | `STRING_AGG`（按 `SqlServerVersion` 决定，2017+ 才支持，否则抛异常）                                                 | `GROUP_CONCAT`                                      |   |    |   |       |
| 批量插入          | `SqlBulkCopy`                                                                                         | 不支持（多行 VALUES）                                      |   |    |   |       |

**版本感知**：`SqlServerMethodResolver` 构造接收 `SqlServerVersion` 枚举，同一 SQL 片段在不同版本生成不同函数（如 `TRIM` 在 2017+ 用原生）。

## 10. 关键设计权衡与技术债

### 已经做对的

1. **解析器 / 组装器 / 方言三层分离** —— 支持 7 个数据库而代码不臃肿的根本原因
