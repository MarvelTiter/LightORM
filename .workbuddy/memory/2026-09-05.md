## 通读 LightORM 项目并生成技术大纲

产出 `doc/项目大纲.md`（约 11 章 + 2 个附录），覆盖双主线架构、方言层、执行层、源生成器、AOT 设施、缺口清单与阅读路线。

### 项目核心认知

- **双主线**：A 表达式→SQL（IExpSelect<T1..Tn> → SelectProvider → SelectBuilder → ExpressionResolver → ISqlMethodResolver → IDatabaseAdapter）；B DbDataReader→对象（SqlAdo → InternalDataReader → ExpressionBuilder.BuildDeserializer<T> → Expression.Compile()）。两线在 `Extension/SelectResultExtensions.cs` 的 InternalToList 汇合。
- **三层职责分离**：解析器管片段生成 / Builder 管结构组装 / Adapter 管方言翻译。
- **易混命名**：`src/LightORM/Providers/` 是核心库内 SQL 生成 Provider；`src/Providers/` 才是独立数据库方言 NuGet 包。

### 实测发现的坑（后续可做）

- `LightOrmTableContextGenerator/TableContextGenerator.CreateDeserializeMethod.cs`：生成的方法体是 `throw new NotImplementedException()`，完整实现整体注释掉了 → **AOT 静态反序列化路径当前不可用**，实际仍全部走 `ExpressionBuilder` 动态编译。
- `Cache/DeserializerCache.cs`：空壳，直接 throw NotImplementedException。
- `Utils/ExpressionAotHelper.cs`：空桩。
- `SqlExecutor/OrignalSqlExecutor.cs`：标记 `[Obsolete]` 但仍是主实现。
- `AssemblyInfo.cs`：`ShowSqlExecutorDebugInfo` / `ShowExpressionHashCodeDebugInfo` 默认 true。
- `IsAOTRuntime` = `!RuntimeFeature.IsDynamicCodeSupported && AOTSupported`，`AOTSupported` 由 `ExpressionSqlBuilder.cs:74` 置 true。

### 有用的速查

- 表达式缓存：FNV-1a 64 位（`Utils/Vistors/ExpressionHasher.cs`），参数名与常量值默认不参与哈希，`NeedToExtractValues` 触发 `ExpressionValueExtract` 每次重新取值 —— 结构解析一次 / 值提取每次。
- 反序列化：缓存键 = `类型 FullName + 每列「列名:DataType:AllowDBNull」`；四路类型分派 = 元组 / 基础类型 / 匿名（Expression.New）/ 具名（MemberInit）；每成员三段 = 取值 GetXxx(i) + 转换 + `IsDBNull ? default : value` 三元。
- 新增数据库方言 = 实现 5 个类：Custom{DB}Adapter / {DB}MethodResolver / {DB}Provider / {DB}TableHandler / {DB}TableOptions。
