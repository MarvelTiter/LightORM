## 反序列化器「源生成器方案」可行性评估材料

用户诉求：当前 `ExpressionBuilder` 按 `DbDataReader` 实例构建委托（列类型/可空/序号都准确，首次编译后快）；想看改成「按实体类型生成代码」的产出长什么样再评估。

产出目录 `doc/aot-preview/`（README.md + 5 个代码文件 + `_verify/` 验证工程）。

### 方案核心

生成器只有 `T`、看不到 reader，所以必须把「类型决策」从编译期推迟到运行期 —— 但**只推迟一次**：

```
编译期(生成器)            运行期一次(Bind)              运行期每行(Read)
列集合/所有转换分支展开  →  GetName+GetFieldType → Plan  →  GetXxx(ordinal) 精确调用
                          (ordinal + FieldKind，按 schema 缓存)
```

三档：**A 纯 GetValue**（装箱，2~4×慢）/ **B Compact**（switch 收进运行库 `DataReaderReaders`，~3 行每列）/ **C Fast**（switch 展开到实体自身 `Read_Xxx`，~25 行每列，性能对标 Expression）。推荐按列数自动选档（≤20 列 Fast）。

### 关键设计决策（已定）

- **用「对象初始化器 + private static Read_Xxx」而不是 `var p=new T(); p.X=...`**：`Product.CreateTime` 是 `init`，方法体内赋值编译不过；对象初始化器是唯一能写 init 属性的地方，顺带解决 Flat 只读宿主。
- **无条件 `IsDBNull` 检查，不做 AllowDBNull 预判**：见下方「发现的坑」。
- **列名匹配生成三份 case**（原样/全大写/全小写）覆盖 MySQL/Oracle/PG，C# 字符串 switch 自动降级成静态字典。
- **Plan 缓存 key 不查 `GetSchemaTable()`**，只用 `FieldCount + GetName + GetFieldType`（SQLite 等 provider 的 GetSchemaTable 很慢或返回 null）。

### 又挖到的坑（接昨天）

- `ExpressionBuilder.GetTargetValueExpression`：`if (AllowDBNull)` 才生成 `IsDBNull` 检查。provider 报 `AllowDBNull=false` 但实际返回 NULL（**LEFT JOIN 右表全 NULL，MySQL 常见**）→ `GetInt32` 直接抛异常。生成器方案无条件检查，反而更稳。
- `LightORM.Utils.JsonHandler` **主库里不存在**，`04` 示例依赖它，需新增：`Deserialize<T>(string)` 泛型版替代现有 `RecordFieldStringDeserializer(string, Type)` 反射重载（后者 AOT 不安全）。
- `Cache/DeserializerCache.cs` 空壳（昨天已记），正好可作为 `ReaderPlanCache<TPlan>` 的落点。

### 接入点

`ITableEntityInfo<T>.DataReaderDeserializer` 已经是 `Func<IDataReader, T>` —— **生成器产出签名完全一致，接入零适配**。
`BuildDeserializer<T>` 改双轨（16 个调用点）：生成器产物优先，Expression 回退匿名类型/Tuple/标量；AOT 下回退改为抛异常，靠已有的 `LightOrmAotAnalyzer` 在编译期报诊断。

### Avalonia 12 与 WPF/旧版 Avalonia 的差异（踩坑记录）
- CheckBox 没有 Checked/Unchecked 路由事件，用 `IsCheckedChanged`。
- `IClipboard.SetTextAsync` 移除，改为扩展方法 `ClipboardExtensions.SetTextAsync`（namespace `Avalonia.Input.Platform`），底层走 `SetDataAsync(IAsyncDataTransfer)`。
- `FolderPickerOpenOptions` 在 `Avalonia.Platform.Storage` 命名空间。
- XAML 属性值以 `{` 开头必须 `{}` 转义（如 `{0}` 占位符文案）。
- Avalonia 12 无 `BindingPlugins.DataValidators` 可访问 API。

### MVVM 风格修正（用户反馈，后续 Avalonia 项目遵循）
- 全选 CheckBox：不用 code-behind 事件，改 `[ObservableProperty] public partial bool SelectAll` + `partial void OnSelectAllChanged(bool)` 钩子，XAML 直接 `IsChecked="{Binding SelectAll}"`。
- 打开对话框：不在 axaml.cs 里 new Window，统一走 `IDialogService`（View 层实现持有 owner 窗口，`ShowDialog(owner)`）；VM 只调接口方法。code-behind 仅保留窗口生命周期事件（OnClosing 退出确认）。
- 新增 `ExceptionWindow`：异常详情对话框（类型/消息/完整堆栈/复制详情），`IDialogService.ShowExceptionAsync(ex, title)`，Connect/Build/SaveToLocal 的 catch 全部改用它。
- Avalonia XAML 编译器要求窗口有 public 无参构造（AVLN3001），带参构造的窗口需补一个无参构造链式调用。
